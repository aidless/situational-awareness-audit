# 判定者间一致性实验 · 预注册

> 本文在收集任何人类判定数据**之前**写定，sha256 记录于 `PREREG.sha256`，由 CI 每次运行重算比对。
> 修改本文必须留下新版本并重算哈希，与主审计的封存纪律一致。

日期：2026-10-25　　实验编号：IR-1

---

## 1. 这个实验要回答什么

主审计的结论受一个人（审计者）的口径选择影响：去重规则、排除决定、数据源优先级，都是单人定的。README 里把这写成一句边界声明，但声明不是测量。

本实验把这句话变成数字，并且——这是更重要的部分——**定位分歧出现在哪一类断言上**。

预注册假设：

| 编号 | 假设 | 反证条件（出现即视为不成立） |
|---|---|---|
| H1 | 纯数字类断言（`quantitative_trend`、`capability_gain_decomposition`）的判定一致率显著高于需自造定义类（`conversion_factor`、`methodological_recommendation`） | 两类一致率差 < 20 个百分点，或方向相反 |
| H2 | 给判定协议（条件 B）后，需自造定义类的分歧明显减少 | B 条件相对 A 条件的分歧条目数下降 < 25% |
| H3 | 排除项（对照）在盲判条件下，独立判定者同样无法给出阈值 | 多数判定者为该条给出明确 hit/partial/miss |

H1 成立 → 支持「可证伪性取决于量是否有公认操作化定义」。  
H2 不成立 → 说明「协议」并没有解决歧义，只是把歧义搬了个位置，这是对我自己方法论的实质性打击。  
H3 不成立 → C24 的排除决定失去外部支持，应恢复计分或至少降级为 ambiguous。

## 2. 设计

**组内设计，固定顺序**：同一判定者先做条件 A（只给摘录 + 阈值，不给协议），提交并锁定后，再做条件 B（同批条目 + 协议）。

选组内而非组间的理由：判定者稀缺（我只有有限的可用人手），组间设计需要两倍人数。  
代价必须写明：**存在学习效应与锚定效应**——做完 A 再看 B，B 的一致率上升有一部分可能来自「已经想过一遍」，而非协议的功劳。故 H2 的效应量只能当上界，不能当净效应。报告中必须写这句。

**抽样**：`packet_gen.py --n 12 --seed 20261025 --strict`，按 `claim_type` 分层轮转，另加 1 条对照（C24，`excluded_from_scoring=true`）。抽样结果记录在包的 `_map.json`，不得在看到判定结果后重抽。

**盲化**：
- 不给 `notes`（含审计者推理与倾向）
- 断言 ID 替换为 `IT-xx`，`--strict` 抹掉他条交叉引用
- 顺序按 seed 打乱
- 判定者不得检索原文或其他项目文件

## 3. 结局指标

**测量字段是可判定性评级（`judgeability`），不是 hit/miss。**

原因：13 个条目里 12 个到期日在 2027–2028 年。让判定者对未发生的事判 hit/miss 本身不成立，得到的一致性数字也没有意义。故主问题改为「假设到期日已到且数据齐全，这条断言能否被无争议地判定」，取值 `mechanical` / `contested` / `unjudgeable`。这是测量工具的清晰度测试，对全部条目今天就能答。

当前判定值（hit/partial/miss/ambiguous/unavailable）保留为**可选副题**，仅记录、不参与假设检验——它对数据已存在的少数条目有意义，对多数条目应当留空。

**主要结局（描述性）：按 `claim_type` 的完全一致率。** 不使用 kappa 做假设检验，理由见 §4。

**次要结局**：Fleiss kappa（≥3 判定者）或两两 Cohen kappa；线性加权 kappa（仅 hit/partial/miss 成对完备的条目）。

**第三结局（归因）**：`ambiguous` / `unavailable` 的理由码分布。这是本实验信息量最大的部分——**kappa 只说明「不一致」，理由码说明「为什么不一致」**。若分歧集中在 R2（阈值表述歧义）与 R4（无法操作化），则指向阈值设计；若集中在 R1（数据源不可得），则指向证据可得性，与阈值设计无关，不应算作协议缺陷。

## 4. 样本量：为什么不做 kappa 推断

用 13 个条目、3 名合成判定者做的端到端自测（`selftest_pipeline.py`）给出的 bootstrap 95% CI 是 **[-0.188, 0.424]**，宽度 **0.612**。

这个宽度意味着：k=0.45 与 k=0.05 在当前样本量下无法区分。按条目数缩放，即使把条目加到 23 条，CI 宽度仍约 0.46。**在这个规模上，任何「kappa 达到 0.6 即为 substantial」的陈述都是过度解读。**

故本实验定位为**描述性测量 + 归因**，不设 kappa 显著性门槛，也不报 p 值。这不是保守，是因为报了就错。

若将来要把它做成可推断的结论，需要：条目 40+（可跨多份文献复制该协议），或判定者 8+（用一般化理论分解 rater × item 方差）。这超出 IR-1 范围，记为 IR-2 的候选。

## 5. 排除规则

判定者的整份评分作废（不进分析）的条件，按顺序判断：

1. 明确承认检索过原文或其他项目文件
2. 同一条件下超过 40% 条目留空
3. 单条目平均耗时 < 20 秒（13 条 × 2 条件 = 26 条，总耗时低于 9 分钟视为敷衍）

不因「判定值与我不同」而作废任何评分。**这条必须写下来，因为它是这类实验最常见也最致命的作弊方式。**

## 6. 与主审计的关系

- 本实验**不修改任何阈值**，不触碰 `data/claims.yaml` 与 `data/seal.json`
- 若结果显示某条阈值表述有歧义（理由码 R2 集中），处理方式与 C10 折算系数修正相同：**明示修正 + 归档旧封存 + 重新封存**，不得悄悄改
- 若 H3 被推翻，C24 的排除决定需在报告中更正，并说明当初排除的依据不足

## 7. 预期的诚实风险

| 风险 | 说明 |
|---|---|
| 判定者同源 | 若判定者都是同一背景（如都是我的同学），一致性会被人群同质性抬高，与协议质量无关 |
| 学习效应 | 见 §2 |
| 判定者知道这是审计者的项目 | 可能倾向于顺从既有判定。故 A 条件必须在看到任何判定结果前完成 |
| 13 条的分层 | 每层 1–3 条，一致率的分母极小，单条翻转可达 33–100 个百分点。报告须逐层给出条目数，不得只报总一致率 |
